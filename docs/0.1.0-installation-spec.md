# 0.1.0 Debian 13 Standard: InstallationSpec foundation

`0.1.0-dev.1` introduces the immutable installation contract without exposing an administrative mutation API or booting an installer yet.

## Contract

An InstallationSpec is a server-created immutable snapshot for one provisioning attempt. It pins:

- machine identity,
- driver ID and driver version,
- OS release and architecture,
- profile ID and immutable profile revision,
- artifact identities, names and canonical SHA-256 digests,
- storage and security intent snapshots,
- lifecycle credential identity, never the credential secret,
- creation timestamp and actor.

The store exposes create and read operations only. There is deliberately no update operation. A different desired state creates a different InstallationSpec.

## Security boundary

This slice does not expose `CreateInstallationSpec` through HTTP or the Studio. Creating or arming an installation is an administrative action and remains unavailable until AegisPXE has an explicit authenticated operator boundary.

Lifecycle credential values are not part of the spec. Only the non-secret credential identity is pinned so later components can resolve the secret through the dedicated secret-storage boundary.

Artifacts must carry a stable identity and a canonical `sha256:<64 lowercase hex>` digest. Resolving and verifying those artifacts is owned by the upcoming Debian 13 driver/artifact slice; dev.1 only makes the digest pinning contract impossible to omit.

## Audit

Spec creation and its `INSTALLATION_CREATED` event are committed atomically. The operational log records IDs, driver/profile revisions and actor, but never lifecycle credential material.

## Gate for dev.1

- invalid specs fail closed,
- a spec references an existing machine,
- installation ID and creation time are server-assigned,
- artifact identities and SHA-256 digests are mandatory,
- caller mutation after creation cannot alter the persisted snapshot,
- reading the spec round-trips the exact immutable snapshot,
- creation emits exactly one auditable `INSTALLATION_CREATED` event,
- no administrative HTTP mutation endpoint exists yet.
