# 0.1.0 Operator Console and Debian Standard wizard

`0.1.0-dev.8` turns the bootstrap operator boundary into a usable provisioning surface without weakening the public PXE/Studio listener.

## Two HTTP roles

AegisPXE deliberately separates the public provisioning listener from the bootstrap operator access path.

Default package configuration:

```text
AEGISPXE_LISTEN=127.0.0.1:8090
AEGISPXE_OPERATOR_LISTEN=127.0.0.1:8091
AEGISPXE_OPERATOR_KEY=/var/lib/aegispxe/operator.key
```

`AEGISPXE_LISTEN` continues to serve discovery, assignment-gated public boot material and read-only Studio views. Deployments may bind that listener to the provisioning network as required by PXE clients.

`AEGISPXE_OPERATOR_LISTEN` is a second listener for the same application handler but is accepted only when its configured host is a loopback IP literal. `127.0.0.1` and `::1` are valid. A LAN address, wildcard address or hostname fails startup rather than exposing the bootstrap Operator Console unexpectedly.

Set `AEGISPXE_OPERATOR_LISTEN=disabled` only when the dedicated local operator listener is intentionally not required.

## Access through SSH

The bootstrap Operator Console is designed to be used locally or through an SSH port forward until AegisPXE gains a separately reviewed direct TLS/trusted-proxy deployment contract.

Example from an administrator workstation:

```bash
ssh -L 8091:127.0.0.1:8091 <admin>@<aegispxe-host>
```

Then open:

```text
http://127.0.0.1:8091/ui/operator/login
```

The bootstrap key remains on the AegisPXE host:

```bash
sudo cat /var/lib/aegispxe/operator.key
```

The key file is created with mode `0600`. Its value is never intentionally written to normal logs. Successful login exchanges the key for a short-lived server-side session with an HttpOnly, SameSite=Strict cookie and per-session CSRF token.

The public provisioning-network HTTP listener remains read-only for operator mutations. Proxy headers such as `X-Forwarded-Proto` are not trusted as proof of secure transport.

## Operator Console

`/ui/operator/` is an authenticated control surface separate from the public read-only Studio. It currently exposes only the provisioning mutations needed for the Debian 13 Standard vertical slice:

- set Machine policy to `pending`, `local`, `provision` or `blocked`,
- create a Debian 13 Standard immutable InstallationSpec,
- arm an unassigned InstallationSpec for its Machine,
- cancel an armed assignment,
- end the operator session.

A cancelled or consumed InstallationSpec is not recycled. A new provisioning attempt receives a new immutable InstallationSpec.

Every accepted store mutation retains the authenticated actor `bootstrap:operator` and the same request ID used by the operator HTTP request.

## Debian 13 Standard wizard

The wizard is intentionally not an arbitrary InstallationSpec editor.

The operator supplies only desired state that belongs in the resolved ProfileSnapshot or concrete installation target:

- eligible `provision` Machine,
- hostname,
- locale,
- keyboard layout,
- timezone,
- key-only administrator identity,
- one or more SSH public keys,
- optional additional Debian packages,
- explicit whole-device target disk.

The following values are server-owned and cannot be supplied or overridden by the browser:

- driver ID `debian13`,
- driver contract version `1`,
- Debian release `13`,
- architecture `amd64`,
- trusted Debian artifact source URLs,
- installer version,
- SHA-256 digests and artifact sizes,
- artifact provenance,
- Standard security baseline,
- lifecycle credential identity,
- InstallationSpec ID and creation time.

Before any Debian metadata or artifact download, AegisPXE validates the selected Machine, ProfileSnapshot and target whole-disk path. A partition such as `/dev/vda1` therefore fails before artifact resolution.

After local input validation, the server runs the normal Debian artifact resolver. The signed `trixie/InRelease` trust chain, verified installer checksum manifest and final kernel/initrd SHA-256 verification remain mandatory. Only the resulting verified descriptors enter the immutable InstallationSpec.

Creating the spec does **not** arm it. The operator is redirected to the read-only InstallationSpec detail and can review the exact Machine, target disk, ProfileSnapshot and verified artifact provenance before a separate explicit arm action enables the next PXE provisioning boot.

## Response bounds

Each Debian upstream HTTP operation remains bounded to two minutes. Artifact resolution performs multiple signed-metadata and artifact requests sequentially, so the AegisPXE HTTP server uses a ten-minute write timeout for the complete bounded request path rather than the previous 15-second response window.

The operator listener uses the same bounded server timeouts. Operator form bodies remain bounded at 96 KiB.

## Observability

Authentication/session decisions continue to use `component=operator.auth`.

Operator wizard activity uses `component=operator.installation` with operations including:

- `resolve_artifacts`,
- `create_spec`.

Useful fields include:

- `request_id`,
- `machine_id`,
- `installation_id` after creation,
- `actor`,
- Debian release and installer version,
- kernel/initrd digest after successful trust resolution,
- normalized target disk after successful spec creation,
- `result`,
- stable `error_code` and safe `cause` on rejection/failure,
- `duration_ms`.

SSH public-key payloads, bootstrap keys, session tokens, CSRF tokens and artifact bytes are not intentional log fields.

## Lifecycle boundary

Creating, reviewing or arming an InstallationSpec still does not invent installer progress. Public boot reads remain retryable and non-consuming. `INSTALLER_STARTED` is emitted only after the later authenticated installer telemetry boundary accepts a real start report.

Cryptographic boot trust is still required before lifecycle-credential release or any other secret-bearing installer operation.
