# 0.1.0 Debian 13 Standard: BootSpec contract

`0.1.0-dev.3` introduces the typed `BootSpec` as a deterministic derivative of an immutable `InstallationSpec`.

## Separation

The two specifications have different jobs:

- `InstallationSpec` is the authoritative immutable provisioning assignment: machine, driver contract, OS target, profile revision, verified artifact provenance, storage/security intent and lifecycle credential identity.
- `BootSpec` is transport-facing data only: installation identity, driver contract identity, digest-pinned kernel/initrd references, bounded kernel arguments and a non-secret seed reference.

A `BootSpec` is not a second source of truth and is not persisted independently. It is re-rendered from the immutable InstallationSpec by the pinned driver contract.

## Debian 13 rendering

The Debian 13 driver contract currently has:

- driver ID `debian13`,
- driver contract version `1`, independent from the AegisPXE application version,
- target Debian `13` on `amd64`,
- exactly one `linux` artifact,
- exactly one `initrd.gz` artifact.

Before rendering, the driver requires both artifacts to:

- pass the generic InstallationSpec artifact contract,
- use the same pinned Debian installer version,
- use identical Debian `trixie` provenance,
- originate from the trusted `https://deb.debian.org` origin,
- have source paths matching their pinned installer version and artifact role.

A mismatched driver contract version or mixed artifact set fails closed.

## BootSpec bounds

A BootSpec:

- contains exactly one kernel reference,
- contains one to four initrd references,
- contains at most 32 bounded kernel arguments,
- rejects duplicate artifact IDs and duplicate kernel argument keys,
- rejects secret-looking argument keys,
- contains no upstream artifact URL,
- contains no lifecycle credential value,
- uses a bounded relative seed reference without query string or fragment.

The current Debian renderer emits only static public kernel arguments (`auto=true`, `priority=critical`, `interface=auto`).

## Lifecycle rule

Rendering or fetching a BootSpec, kernel, initrd or seed does not imply `INSTALLER_STARTED` and must not consume a provisioning assignment. The lifecycle advances only after an authenticated installer event is accepted according to `LIFECYCLE.md`.

## Scope boundary

This slice does not yet:

- persist/cache verified artifact bytes,
- expose BootSpec or installation material over HTTP,
- render the Debian unattended seed itself,
- arm a provisioning assignment,
- issue lifecycle credential values,
- mark any installer lifecycle stage.
