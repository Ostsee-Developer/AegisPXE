# 0.1.0 Debian 13 Standard: unattended seed

`0.1.0-dev.4` introduces the first deterministic Debian 13 Standard seed renderer. It renders native Debian Installer Preseed syntax from the immutable InstallationSpec and its resolved ProfileSnapshot.

## Supported driver contract

Debian driver `debian13` version `1` currently accepts only the Standard vertical slice:

- Debian 13 amd64,
- unencrypted `whole-disk` storage,
- ext4,
- explicit whole-device target disk,
- root login disabled,
- SSH password authentication disabled,
- automatic security updates enabled,
- SSH-key-only administrative account,
- explicit passwordless sudo for that administrator.

Unsupported desired state fails with `DRV001_DRIVER_SPEC_UNSUPPORTED`. The driver never silently approximates encryption, authentication or storage policy.

## Preseed output

The rendered SeedBundle pins native installer values for:

- locale, keyboard and timezone,
- DHCP/network interface selection and immutable hostname,
- Debian package mirror,
- explicit partitioning target,
- regular whole-disk atomic layout,
- explicit GRUB target,
- standard task and requested packages,
- OpenSSH server, sudo and unattended-upgrades,
- SSH-key-only administrator creation,
- sudoers validation,
- sshd configuration validation,
- automatic update configuration,
- final reboot.

Debian Installer creates the normal administrative user natively with `passwd/user-password-crypted` set to `!`, so the account remains disabled during installation. The late hook installs the pinned SSH keys, sudoers policy and sshd hardening first, then changes the shadow password field to the non-locking unusable `NP` marker. OpenSSH password and keyboard-interactive authentication remain disabled, so the account is usable through public-key authentication without introducing a reusable password secret.

## Seed security

The SeedBundle contains installation configuration and SSH public keys but no lifecycle credential value, password or private key. Normal operational logs never contain SeedBundle content or public-key values.

The seed is **not exposed over HTTP in dev.4**. Debian network Preseed uses a URL fetch after networking, while AegisPXE requires installation-scoped seed authentication and forbids credentials in URLs/query strings. The transport/authentication design therefore remains closed until a later slice can prove a secret-safe credential channel.

Rendering a seed is not an installer lifecycle event and never implies `INSTALLER_STARTED`.

## Artifact boundary

A verified HTTP artifact loader is prepared in dev.4. It fetches only a caller-supplied pinned Descriptor, bounds response size, restricts redirects to the pinned origin, and verifies exact byte size plus SHA-256 before returning content.

The loader is **not registered as a public HTTP route in dev.4**. Public artifact serving waits for an armed Machine-to-Installation assignment so AegisPXE does not expose an unauthenticated bandwidth-amplification path.

Fetching or verifying an artifact does not advance installation lifecycle state.

## Observability

Operational seed render logs use:

- `component=driver.debian13`,
- `operation=render_seed`,
- `request_id`,
- `machine_id`,
- `installation_id`,
- driver/profile revisions,
- normalized target disk,
- rendered byte count,
- `result`,
- stable `error_code` on failure,
- `duration_ms`.

Verified artifact loader logs use:

- `component=artifact.loader`,
- `operation=fetch_verified`,
- `request_id`,
- `installation_id`,
- artifact ID/name/digest,
- verified byte count,
- `result`,
- `error_code` on failure,
- `duration_ms`.

Seed content, artifact content, SSH-key values and credential material are never intentional log fields.

## Tests

The focused tests prove:

- target disk is rendered into both partitioning and GRUB configuration,
- native disabled-user creation and key-only administrator hardening are present,
- unsupported Standard state is rejected with a stable code,
- seed logs contain correlation data but not seed/key material,
- artifact hash mismatch fails closed with correlated logging,
- immutable ProfileSnapshot slices do not alias caller-owned data.
